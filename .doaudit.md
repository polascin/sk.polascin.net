# Opakovaný komplexný audit pre sk.polascin.net

## Cieľ

Vykonaj opakované behy hĺbkového komplexného auditu statického PHP webu **sk.polascin.net** podľa [`.audit.md`](.audit.md) (bezpečnostný audit OWASP, integrita PHP/HTML/CSS kódu, kvalita databázových dotazov k citátom, SEO, responzívny dizajn, prístupnosť WCAG 2.1 AA, súlad s GDPR bez zdravotných údajov a slovenská jazyková a medicínska korektúra) a dodržiavaj bezpečnostné pravidlá uvedené v `.audit.md`.

## Postup

1. Spusti audit podľa kontrolného zoznamu v [`.audit.md`](.audit.md).
2. Zaznamenaj všetky nálezy vrátane ich závažnosti (🔴/🟠/🟡/🟢), príčiny a odporúčanej opravy.
3. Implementuj bezpečné a relevantné opravy a vylepšenia nájdené v aktuálnom kole.
4. Over zmeny relevantnými projektovými kontrolami:
   - PHP syntax lint: `php -l <file.php>` pre všetky zmenené PHP súbory (a rekurzívne pre celý repozitár)
   - Well-formed XML v `sitemap.xml`: `php -r 'exit((new DOMDocument())->load("sitemap.xml") ? 0 : 1);'`
   - Statická analýza (ak sú PHAR nástroje nainštalované cez `tools/install-dev-tools.ps1`):
     - `php tools/phpstan.phar analyse --no-progress`
     - `php tools/php-cs-fixer.phar fix --dry-run --diff`
   - Kontrola citlivých hodnôt: žiadne heslá/kľúče v sledovaných súboroch (`git grep`)
   - Manuálna kontrola HTTP hlavičiek a stavových kódov: `curl -I https://sk.polascin.net/`
   - Kontrola blokovania: `blocks/`, `docs/` (okrem verejne odkazovaných), interné súbory a `db.config.php` → 403; `privacy.php`, `terms.php`, `sitemap.xml` → 200
   - Funkčná kontrola citátov (`refbook.sk.php?data=<id>` a neplatný/nekorektný vstup) a rozcestníka `index.php`
   - Kontrola všetkých webových odkazov podľa sekcie 7 v `.audit.md` a oprava nefunkčných adries
5. Zapíš výsledky, vyriešené nálezy a poznatky pre ďalšie behy do [`.audit.md`](.audit.md) ako nový „Beh #X“ s odvolávkami na opravené súbory.
6. Opakuj kroky 1 až 5, kým audit nenachádza žiadne nové bezpečne opraviteľné chyby alebo bugy.

## Bezpečnostné pravidlá

- Nevykonávaj nebezpečné alebo nekompatibilné automatické opravy bez samostatného posúdenia ich dopadov.
- Známe výnimky a nálezy, ktoré nie je možné bezpečne opraviť, zdokumentuj spolu s odporúčaným ďalším postupom.
- Pri bezpečnostných nálezoch uprednostni obranné riešenia a minimalizuj riziko regresie (prepared statements, validácia vstupov, escapovanie výstupov, blokovanie citlivých ciest v `.htaccess`).
- Nikdy necommitni `db.config.php` ani iné tajné hodnoty; nezverejňuj heslá ani kľúče.
- Zachovaj primárny slovenský jazyk a odborný medicínsky charakter obsahu.

## Dokončenie

Po úspešnom ukončení všetkých auditných kôl:

1. Skontroluj finálny diff a stav repozitára (`git status`, `git diff --stat`).
2. Uisti sa, že všetky PHP súbory prechádzajú `php -l`, `sitemap.xml` je well-formed a webové odkazy sú skontrolované a opravené.
3. Commitni všetky relevantné zmeny s výstižnou správou (nepoužívaj `git push`, pokiaľ to používateľ výslovne nežiada; pri push na `main` sa spustí automatický deploy cez GitHub Actions).
4. Over správnosť nasadenia na produkčnej stránke vrátane HTTP odpovede, bezpečnostných hlavičiek a relevantných funkčných a stavových kontrol.
